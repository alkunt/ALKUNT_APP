# ALKUNT — حزمة الخادم المستقل

هذه نسخة مستقلة من التطبيق مهيأة لـ **خادم Linux يدعم Docker أو Node.js 24**. ليست ملفات HTML ثابتة، ولا تعمل بمجرد نسخها إلى public_html في استضافة PHP، ولا تُرفع كقالب داخل Odoo.

لم يُحدَّد نوع خادم المالك؛ لذلك توافق الحزمة مع استضافتك الفعلية لم يُتحقق منه. لم يُغيّر الموقع الحالي المستضاف لدى ChatGPT.

## ما تحتويه
- الواجهة العربية والإنجليزية ولوحة إدارة المحتوى والعروض والمدونة والأوامر.
- تسجيل دخول بالبريد وكلمة المرور مستقل عن ChatGPT؛ كلمات المرور مجزأة باستخدام scrypt وجلسات HTTP-only، مع تحديد لمحاولات الدخول.
- SQLite للبيانات وملفات محلية محمية للتنزيل. لا تعتمد هذه النسخة على Cloudflare D1 أو R2.
- داخل الكويت: طلب رابط دفع ثم إرساله من المالك داخل حساب العميل. خارج الكويت: تحويل يدوي وإيصال. لا تفعيل قبل تأكيد استلام الدفع.
- حذف من مكتبتي مستقل عن الأقسام والمشتريات، وحذف نهائي منفصل للإدارة.
- أدوات نسخ احتياطي واستيراد الكتالوج وفحص متطلبات الإطلاق.
- ملفات Docker وCompose ومثال Nginx وملف إعدادات دون أسرار.

## النشر باستخدام Docker
1. فك الملف في مجلد التطبيق على خادمك.
2. انسخ `.env.example` إلى `.env` واجعل صلاحياته 600.
3. اضبط `APP_ORIGIN` على رابطك الكامل مثل `https://learn.alkunt.com` دون شرطة مائلة أخيرة. لا تستخدم هذا المثال ما لم تضبط هذا النطاق فعليًا.
4. شغّل:

```bash
docker compose build
docker compose up -d
docker compose exec app node scripts/create-owner.mjs
```

5. أدخل كلمة مرور جديدة قوية من 12 حرفًا على الأقل. الأداة تخفي الإدخال. لا توجد كلمة مرور افتراضية أو مضمنة في الملفات. حساب المالك هو `alkunt@yahoo.com`.
6. اربط الدومين بالخادم واضبط HTTPS وNginx باستخدام المثال `deploy/nginx.conf.example` بعد استبدال النطاق ومسارات الشهادة. يستمع التطبيق على `127.0.0.1:3000` بالخادم عبر Docker.
7. افتح موقعك وسجّل الدخول، ثم أكمل الإعدادات والمحتوى.

لا تحذف volume المسمى `alkunt-data`: يحتوي قاعدة البيانات والمرفقات. لا تستخدم `docker compose down -v` على موقع يحتوي بيانات تريد الاحتفاظ بها. هذه الحزمة مهيأة لنسخة تطبيق واحدة على خادم واحد؛ لا تشغّل عدة نسخ تشارك SQLite عبر قرص شبكي.

## النشر دون Docker
يتطلب Node.js 24 وnpm وخدمة لإدارة العملية وHTTPS عبر خادم وسيط.

```bash
npm ci
npm run build
node --env-file=.env scripts/create-owner.mjs
node --env-file=.env node_modules/next/dist/bin/next start --hostname 127.0.0.1 --port 3000
```

أدر الأمر الأخير باستخدام systemd أو مدير عمليات مناسب. يجب تمرير `.env` عند تشغيل التطبيق والأدوات؛ Next يقرأ ملفات env في تشغيله المعتاد أيضًا. لا تستخدم `COOKIE_SECURE=false` إلا لاختبارات localhost، ولا تعرّض مجلد data عبر Nginx.

## إعدادات مطلوبة قبل فتح البيع
- أدخل تعليمات التحويل البنكي الفعلية، العملة والضريبة المناسبة في لوحة التحكم، ثم فعّل البيع عندما يصبح المحتوى جاهزًا.
- أضف نصوص الخصوصية وشروط الاستخدام والاسترجاع المعتمدة من المالك. لم توضع بيانات بنك أو مدد استرجاع أو ادعاءات قانونية مفترضة.
- أضف الدروس والمنتجات الحقيقية. الكورسات الأصلية الثلاثة بقيت بحالة «قريبًا» دون اختلاق دروس.
- لا يُقصد بتسجيل البريد في حساب عميل إثبات ملكيته. تتوفر استعادة كلمة المرور من «نسيت كلمة المرور؟» بعد ضبط `RESEND_API_KEY` و`MAIL_FROM` بعنوان إرسال موثّق لدى Resend، وضبط `APP_ORIGIN` على عنوان الموقع. رابط الاستعادة صالح لمدة 30 دقيقة ولمرة واحدة، ويُبطل جميع الجلسات وروابط الاستعادة السابقة بعد نجاح التغيير. إذا لم تُضبط خدمة البريد، يعرض النموذج رسالة واضحة بذلك. تبقى أداة الإدارة متاحة لاستعادة الوصول بعد التحقق من هوية صاحب الحساب.

## الإشعارات والبريد
ولّد مفاتيح جديدة للخادم؛ لا تعِد استخدام أي كلمة مرور أو أسرار من المحادثات:

```bash
node scripts/generate-push-keys.mjs
```

ضع الناتج في `.env`، ثم أعد إنشاء الحاوية:

```bash
docker compose up -d --force-recreate
```

من حساب المالك افتح «إشعارات المالك» واسمح بالإشعارات وسجّل الجهاز واختبرها. نقل الدومين يحتاج اشتراك جهاز جديد.

البريد الآلي اختياري: اضبط `RESEND_API_KEY` و`MAIL_FROM` بعنوان إرسال موثّق لدى مزود الإرسال. وصول البريد أو إشعار الجهاز لم يُختبر على خادمك. الطلبات تُحفظ في لوحة التحكم حتى لو لم تُهيأ هذه القنوات.

## نقل المحتوى القديم
**الحزمة تضم الشفرة والهوية والصور الثابتة، ولا تضم قاعدة الإنتاج أو الملفات التي رفعتها سابقًا إلى الموقع.** مصدر تلك المرفقات مخزن منفصل، وليس مستودع الشفرة. لا تفترض أن ملف PDF أو فيديو موجود لمجرد ظهور معرفه في بيانات المنتج.

1. صدّر JSON من زر النسخة الاحتياطية في لوحة الموقع القديم.
2. احفظ نسخة من كل مرفق وغلاف من حساب المالك، أو أعد رفع الملفات الأصلية في لوحة الموقع الجديد.
3. للاستيراد الفني: شغّل `scripts/import-catalog.mjs` مع ملف JSON. يمكن تمرير مجلد ملفات تُسمى بمعرفاتها، ومع كل ملف ملف JSON بنفس المعرف واللاحقة `.json` يتضمن `purpose` (`cover` أو `content`) و`name` و`type` و`size`.

```bash
node --env-file=.env scripts/import-catalog.mjs dashboard-export.json downloaded-files
```

الأداة لا تستبدل منتجات موجودة، وتستورد إعدادات البيع وهي متوقفة. أي منتج له مرفقات ناقصة يُستورد كمسودة لمنع نشر روابط معطلة. لا تنقل هذه الأداة حسابات ChatGPT أو جلساتها أو الطلبات والمنح؛ نقل سجل العملاء والمشتريات يحتاج مطابقة منفصلة مع حسابات الدخول الجديدة. لا تحذف المصدر القديم قبل التحقق من اكتمال النقل.

## النسخ الاحتياطي والاستعادة
أوقف التعديلات والرفع مؤقتًا للحصول على نسخة ملفات وبيانات متوافقة. داخل Docker:

```bash
docker compose exec app node scripts/backup.mjs /tmp/alkunt-backup
docker compose cp app:/tmp/alkunt-backup ./backups/alkunt-backup
```

احتفظ بنسخة خارج الخادم، دون إتاحتها عبر الويب. للاستعادة أوقف التطبيق، واستبدل قاعدة البيانات ومجلد uploads معًا من نسخة متوافقة ثم أعد التشغيل. لا تكتب فوق قاعدة تعمل، واحفظ نسخة من الحالة الحالية قبل الاستبدال.

إعادة تعيين كلمة مرور المالك:

```bash
docker compose exec app node scripts/create-owner.mjs
```

إعادة تعيين عميل بعد التحقق من هويته:

```bash
docker compose exec app node scripts/create-owner.mjs --reset-user
```

## الفحص
```bash
npm test
npm run build
node tests/http.test.mjs
node --env-file=.env scripts/preflight.mjs
```

الأولان واختبار HTTP اجتازت في بيئة العمل. اختبار HTTP يشغّل خادم إنتاج محليًا بقاعدة مؤقتة وحسابات اختبار، ويفحص رفض انتحال ترويسات ChatGPT، تسجيل الدخول والجلسات والصلاحيات والشراء وتفعيل المحتوى وعزل الحذف من مكتبتي. لا يختبر الدفع البنكي الحقيقي أو الواجهة بصريًا.

لم تتوفر Docker في بيئة التجهيز؛ لذلك ملف Docker مُعد لكن تشغيله على خادمك لم يُختبر. يلزم اختبار الهاتف والمتصفحات وHTTPS واستقبال البريد والإشعارات ورفع الملفات على الاستضافة الفعلية قبل فتح البيع.

## بيانات المسجلين وإدارة الطلبات
- ينشئ `node scripts/export-registrants.mjs` ملف `data/registered-users.json`، ويتحدث الملف عند تسجيل الدخول والتسجيل وتعديل بيانات المنصة. يتضمن الحسابات وبياناتها المحفوظة وحقوق الوصول، دون كلمات مرور أو رموز جلسات أو روابط استعادة.
- يستطيع المالك تنزيل أحدث نسخة من «العملاء والصلاحيات» عبر زر «تنزيل جميع بيانات المسجلين». الملف مخزن خارج المجلد العام، والتنزيل محصور بالمالك.
- النسخة الاحتياطية الكاملة لقاعدة البيانات والمرفقات تنشأ عبر `node scripts/backup.mjs`.
- يظهر للمالك زر «حذف نهائي» في الطلبات والمدفوعات، وينفذ مباشرة دون نافذة تأكيد. يحذف الطلب وإشعاراته ويسجل العملية في سجل النشاط، مع الحفاظ على حق العميل في المحتوى المشترى.
